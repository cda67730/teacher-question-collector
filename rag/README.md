# RAG 回答系統（示範版）

學前融合教育 AI 教師支持系統第二階段：老師提問，系統依技術架構文件的線上流程回答。
**這是另一個 Apps Script 專案，請綁定一份新的試算表**，不要和問卷收集工具混在一起。

```
老師端 web/chat/（GitHub Pages）──POST──▶ rag/gas（Apps Script）──▶ Gemini（分流、向量、生成、檢查）
                                              │
後台（試算表選單「AI 助手後台」）──────────────▶ 試算表：設定、Skill、文件、知識段落、對照表、紀錄
```

## 對照技術文件的元件

| 元件 | 實作位置 |
| --- | --- |
| P03 去識別化（程式） | `Chat.gs` `deid_()` |
| L4 分流器（單一任務 AI） | `Chat.gs` `triagePrompt_()`，與 P06 查詢向量**並行**（`fetchAll`） |
| P04 對話狀態機（程式） | `Chat.gs` `runChat_()`：緊急轉介、超出範圍、追問、建議 |
| P05 Skill 載入器（程式） | 依分流主題載入「Skill」工作表中啟用的 Skill；「一律載入」的永遠載入 |
| P06 混合檢索（程式） | `Knowledge.gs` `search_()`：同義詞擴充＋向量相似度＋關鍵字加分 |
| P07 Prompt 組裝器（程式） | `Chat.gs` `assemble_()`：五層順序 |
| A1 對話 Agent | `Chat.gs`：追問、生成、重寫一次 |
| P08 規則檢查、P09 出處核對（程式） | `Chat.gs` `checks_()` |
| L5 依據與轉介檢查（單一任務 AI） | `Chat.gs` `checks_()`，可在設定中關閉 |
| P10 組合與降級（程式） | 未通過重寫一次，仍未通過改用保守回答 |
| P11 知識庫管理、P12 審核 | 後台「知識庫」：上傳 → 切段 → 向量化 → 待審核 → 核可 |
| P15 紀錄 | 「對話紀錄」「回饋」工作表 |

示範版的簡化：A1 不自己呼叫工具，檢索在生成前由程式先做好；向量存在試算表（壓縮成 int8），數千段以內可用，量大時再移到 PostgreSQL＋pgvector，只需替換 `Knowledge.gs` 的檢索部分。

## 部署步驟

### 1. 建立後端
1. 建立一份**新的** Google 試算表，選單「擴充功能 → Apps Script」。
2. 把 `rag/gas/` 底下的檔案逐一建立並貼上：`Code.gs`、`Chat.gs`、`Knowledge.gs`、`Llm.gs`、`Store.gs`、`Setup.gs`、`Admin.gs`，以及兩個 HTML 檔 `AdminUI.html`、`TraceView.html`（新增檔案時選「HTML」，名稱分別填 `AdminUI`、`TraceView`；Apps Script 不允許指令碼和 HTML 同名）。
3. 專案設定勾選「在編輯器中顯示 appsscript.json」，貼上 `rag/gas/appsscript.json`。
4. 左側「服務」＋ → 新增 **Drive API**（v3）。上傳 Word 檔時會用到。
5. 專案設定 → 指令碼屬性：新增 `GEMINI_API_KEY`。
6. 執行 `setup()`：建立所有工作表、預設設定、4 個 Skill、轉介資源、禁止用語、同義詞，並把你的 email 加進「管理員」。
7. 部署 → 新增部署作業 → 網頁應用程式（執行身分：我；誰可以存取：所有人），複製 `/exec` 網址。

### 2. 設定前端
把網址貼到 `web/chat/config.js` 的 `GAS_URL`，push 後老師端網址為
`https://<帳號>.github.io/<repo>/chat/`

### 3. 放入知識並測試
1. 重新整理試算表，選單出現「**AI 助手後台**」→「開啟後台」。
2. 「知識庫」分頁上傳文件 → 按「看段落」檢查切得對不對 → 按「**核可**」。只有核可的文件會被用來回答。
3. 「測試對話」分頁輸入問題，右邊會顯示每個元件做了什麼（分流結果、載入的 Skill、檢索到的段落與分數、檢查結果）。

## 後台功能

| 分頁 | 可以做什麼 |
| --- | --- |
| 機器人設定 | 名稱、歡迎訊息、固定 system prompt、各步驟使用的模型、溫度、檢索段數與門檻、切段長度、追問次數、是否啟用 L5 檢查 |
| Skill | 新增與編輯 Skill、設定對應主題與「一律載入」、啟用或停用；每次儲存都是新版本，可查看與還原歷史版本 |
| 知識庫 | 上傳 PDF、Word、TXT、Markdown 或貼上文字；查看切好的段落；核可、停用 |
| 測試對話 | 不需邀請碼試問，並看到完整流程紀錄 |
| 對話紀錄 | 指標（檢索命中率、引用率、平均最高分、👍 比例、重寫比例、耗時）、依日期／園所／類型篩選、知識缺口清單、常被引用文件；點任一回合從右側開出流程、整段對話與回答原文 |
| 命中率測試 | 專家寫「老師可能怎麼問」＋「應該找到哪份文件」，一鍵逐題檢索，算出 Hit@K 與 MRR，並標出「有找到但低於門檻」與「前 10 名都沒有」的題目 |
| 其他設定 | 同義詞、禁止用語、轉介資源、邀請碼、管理員：直接在試算表編輯 |

後台權限：只有「管理員」工作表裡的 email 可以使用；其他人也需要有這份試算表的編輯權限才能看到選單。

## 流程觀測面板（聊天頁）

在「邀請碼」工作表把某組邀請碼的「**觀測**」欄設為 TRUE，用這組邀請碼進入聊天頁時，右上角會出現「🔍 流程」，每則回覆下方也有「看流程」。點開後從右側滑出面板，可以看到：分流結果、載入的 Skill、檢索前 10 名段落的分數與門檻（哪些被採用、哪些被引用）、組裝好的 prompt、三項檢查與每一步耗時。正式給老師用的邀請碼不要開。

`web/chat/trace.js` 是面板的呈現程式，聊天頁與後台共用；修改後執行 `node rag/sync-trace.js` 會更新 `rag/gas/TraceView.html`，再貼回 Apps Script。

## 命中率怎麼看

- **線上指標**（對話紀錄分頁）：沒有標準答案，只能看趨勢。檢索命中率低 → 知識庫缺內容；引用率低 → 找到的段落不對題；平均最高分可用來調整 `min_score`。
- **離線命中率**（命中率測試分頁）：有專家標的標準答案，才是真正的命中率。建議每份重要文件寫 2–3 題老師口語問法，每次改切段長度、門檻、同義詞或新增文件後都跑一次，數字下降就是改壞了。

## 注意事項

- **Skill 的主題就是分流的選項**：分流器會從所有啟用 Skill 的「對應主題」中選擇，新增 Skill 時記得填主題。
- **更換向量模型或維度後**，舊文件的向量不能再用，需要重新上傳。
- **PDF 轉文字**用 Gemini 處理，建議單檔 30 頁以內。
- **著作權**：知識段落保存的是文件原文，請確認文件的使用授權。
- Apps Script 每次呼叫需要啟動時間，一次完整回答約 8–20 秒（分流、生成、檢查三次模型呼叫）。
